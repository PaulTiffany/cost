# Claim Certification Stack

This directory implements a six-layer certification system for the
numerical claims in the paper. The deliverable is **the certificate**
itself — `ci/claim_certificate.{json,md}` — generated by a single
command:

```
python ci/claim_certificate.py
```

If the verdict is **PASS**, every registered numeric claim has been
**matched by its registered regex signatures** in `paper/main.tex`,
the registry is internally consistent, every figure has a verified
data → script → asset chain, and the values shown inside figures
are cross-checked against the registry.

### Calibrated framing

The certificate catches **deletion and gross drift**: if a registered
value is removed from main.tex, or if a number changes substantially,
the audit moves to MISSING and the certificate moves to FAIL. The
mtime layer catches stale figure assets. The reverse-coverage sweep
flags numbers in the paper that no claim covers.

The certificate does **not** catch within-table substitution where
the substituted value happens to reappear elsewhere in the paper.
By default, L1 marks a claim FOUND when each of its pattern
signatures matches *somewhere* in main.tex, not when they
co-occur in the same context. Claims marked `"match_mode": "joint"`
require all their patterns within a small window — those are
tighter — but most Tier 2 claims use the default per-pattern-anywhere
mode. So "DeepSeek-Coder 93%" passes if the model name appears
anywhere AND "93%" appears anywhere; if only the row was deleted but
"93%" persists in a different table, the claim still reads FOUND.

The mutation test in `ci/tests/test_audit_substitution.py` documents
this boundary by demonstrating which substitutions the audit catches
and which it doesn't.

The stack exists to make the paper's empirical claims independently
auditable, both for our own discipline and (potentially) for inclusion
in the supplementary as a reproducibility artifact.

## Architecture: six layers, each verifying the layer below

Each layer asks one question. Layers compose: layer N's deliverable
becomes part of layer N+1's input or context.

| Layer | Script | Asks |
|---|---|---|
| **L1** | `claim_audit.py` | Do registered claims appear in main.tex? |
| **L2** | `claim_audit_validator.py` | Is the registry self-consistent? |
| **L3** | `claim_coverage_sweep.py` | Are there numbers in main.tex that no claim covers? |
| **L4** | `figure_lineage_check.py` | Is every figure fresh + lineage-traced? |
| **L5** | `figure_value_check.py` | Do in-figure numerics match the registry? |
| **L6** | `claim_certificate.py` | Aggregate the layers into a single signed artifact |
| **L7** | `citation_integrity_check.py` | Does every \\citep{} resolve to a bib entry? |
| **L8** | `link_integrity_check.py` | URLs well-formed + venue-year right? \\ref/\\hyperref resolve? |
| **L9** | `cross_claim_consistency_check.py` | Do formula-claims and value-claims agree numerically? |

### L1 — Claim audit (`claim_audit.py`)

Walks `CLAIM_AUDIT.md`'s registered claims and verifies each numeric
signature still appears in `paper/main.tex`. Tier 1 (25 critical) and
Tier 2 (75 important) are hand-curated regex patterns; some Tier 2
claims are marked `supplementary_only` and skipped against main.tex.

```
python ci/claim_audit.py --tier critical    # 25 claims
python ci/claim_audit.py --tier important   # 75 (3 supp-only skipped → 72)
python ci/claim_audit.py --tier all         # 100 combined (97 audited)
```

A claim is FOUND if all its pattern signatures match somewhere in
main.tex; DRIFT if some signatures hit but not all; MISSING if none
match. MISSING fails the layer. DRIFT is a warning.

Output: `ci/claim_audit_results.json`.

### L2 — Audit validator (`claim_audit_validator.py`)

Verifies the registry itself, not the paper. Catches the audit being
broken before it can catch the paper being broken. 13 checks across
four groups:

- **A. Structural integrity** — claim counts (25/75), no duplicate IDs,
  every claim has patterns, every pattern compiles, no trivially
  permissive patterns
- **B. Registry consistency** — `CLAIM_AUDIT.md` header counts match
  the script lists, tier-architecture table rows match, Tier 1 header
  reads "(25)", venue label is NeurIPS not ICML
- **C. External reference integrity** — every data file path under "Data
  File Mappings" exists on disk; every harness path under "Verification
  Harnesses" exists on disk
- **D. Audit output sanity** — the latest L1 run reports zero MISS

A failed C-check has caught real path drift in this repo: registry
pointed at `supplementary/experiments/charitable_feasibility_simulation.py`
but the script lives at `supplementary/bridges/`. Validator surfaced
it; registry was fixed.

```
python ci/claim_audit_validator.py
```

### L3 — Reverse coverage sweep (`claim_coverage_sweep.py`)

The reverse direction of L1. L1 asks "do registered claims appear in
the paper?"; L3 asks "are there numbers in the paper that no claim
covers?". This catches claims the registry forgot.

Method: walk main.tex, extract numeric tokens, filter incidentals
(LaTeX dimensions, Section/Figure refs, citation years, TikZ
coordinates inside `\begin{tikzpicture}`, RGB color triples,
`\newcommand` arities, math notation like `2^k` and `2\sigma`,
table layout macros), check survivors against the union of all
claim patterns. Survivors are ranked by likely-claim-ness:
specific decimals first, common small ints last.

Output is a triage list, not a verdict. Coverage % is reported
but doesn't fail the layer. Current coverage: ~66% — the long
tail is mostly axis-tick noise in formulas; the head is genuine
uncovered claims for Tier 3 expansion.

```
python ci/claim_coverage_sweep.py             # summary + write JSON
python ci/claim_coverage_sweep.py --verbose   # full uncovered list
```

Output: `ci/claim_coverage_uncovered.json`.

### L4 — Figure lineage check (`figure_lineage_check.py`)

For each figure: data → script → asset → main.tex. Manifest-driven
(`ci/figure_lineage.json`). Seven checks:

- **A1-A4** — every manifest asset, script, declared data file, and
  declared `outputs_secondary` artifact exists on disk
- **B1-B2** — every `\includegraphics`/`\input` in main.tex has a manifest
  entry (no paper-side orphans); every in-use manifest entry is
  referenced in main.tex (no manifest-side orphans)
- **C1** — asset freshness: `asset_mtime >= max(script_mtime, data_mtimes)`
  for each rendered figure. A failure means the asset is stale relative
  to its source — re-render needed.

The mtime semantic is `asset >= max(script, data)` not `script <= asset
AND data <= script`. Earlier draft of the check fired a false positive
on `constrained_decoding.pdf` because data was newer than script — but
the asset was newer than both, so the chain was actually fresh.

This layer catches the failure mode that motivated the entire stack:
asset committed/built in one repo while the paper was rebuilt in
another, "build clean" reported on a stale rendering.

`outputs_secondary` declarations track non-asset artifacts the script
also writes (typically results JSONs that document computed values
backing textual claims). They're verified for existence and serve as
the bridge to L1's Data File Mappings.

```
python ci/figure_lineage_check.py
python ci/figure_lineage_check.py --verbose
```

### L5 — Figure value check (`figure_value_check.py`)

Cross-validates what reviewers SEE in figures against what the registry
catalogues. For each rendered (non-TikZ) figure: `pdftotext -layout`
the asset, extract numeric tokens, filter incidentals (model version
numbers like `DeepSeek-1.3B`, step-decimal axis ticks like `0.0/0.2/0.5`),
match each survivor against claim patterns. Per-figure coverage % +
uncovered values list.

Catches the case where a figure shows "33%" but the registry expects
"32%", or shows an annotation value (e.g. eigenvalue 4.31) that the
registry doesn't cover at all.

Heatmap-style figures (cross_model_cliff: 97.5%) and bar-chart figures
(constrained_decoding: 85.7%, per_task_correlation: 80.6%) get high
coverage. Schematic figures (algorithm1_storyboard, soft_constraint_cliff:
1-5 k-axis ticks) get low coverage because their numbers are mostly
axis labels.

This layer requires `pdftotext` on PATH.

```
python ci/figure_value_check.py
python ci/figure_value_check.py --verbose --strict
```

Output: `ci/figure_value_check_results.json`.

### L7 — Citation integrity (`citation_integrity_check.py`)

Verifies the citation graph between main.tex and references.bib.
Three checks:

  - **Unresolved citations** — `\\citep{key}` in main.tex with no
    matching `@xxx{key, ...}` entry in references.bib. Would render
    as "??" in the rendered PDF. Always FAIL.
  - **Dead bib entries** — `@xxx{key, ...}` in references.bib but no
    `\\cite*{key}` anywhere in main.tex. Entry never appears in the
    bibliography. WARN by default, FAIL with `--strict`.
  - **Multi-key citations** — `\\citep{a, b, c}` are split and each
    key checked individually.

Citations inside LaTeX comments (full-line or trailing) are skipped
so commented-out references don't false-fire.

Out of scope: DOI/arXiv ID validation (would require network), citation
style consistency, key-to-paper semantic correctness.

```
python ci/citation_integrity_check.py
python ci/citation_integrity_check.py --strict --verbose
```

Output: `ci/citation_integrity_results.json`.

### L8 — Link integrity (`link_integrity_check.py`)

Verifies URLs, internal `\hyperref` targets, and the `\ref`/`\label`
graph in main.tex (with `\input{}` includes recursively expanded so
labels in figure-source files like `figures/related_envelope_combined.tex`
are visible).

Three classes of check:

- **URL integrity** — every `\href{}`, `\url{}`, or bare `https?://`
  link is well-formed; venue-year-bearing URLs (e.g.
  `neurips.cc/Conferences/2026/`) match the declared venue year
  (default 2026); URLs are checked against a whitelist of trusted
  academic prefixes (neurips.cc, openreview.net, arxiv.org,
  4open.science, anonymous.4open.science, etc.). DOES NOT make
  network calls by default.
- **Internal hyperref targets** — every `\hyperref[label]{text}` has
  a matching `\label{label}` or `\hypertarget{label}{...}`. Caught
  one real bug on first run: `fig:rw_quadrant` was defined inside
  `figures/related_envelope_combined.tex` (an `\input{}` include),
  not main.tex directly — analyzer was extended to expand includes.
- **`\ref`/`\label` graph closure** — every `\ref{}`, `\eqref{}`,
  `\autoref{}`, `\cref{}`, `\nameref{}`, `\pageref{}` resolves to a
  defined `\label{}`. Multi-key refs (`\ref{a, b, c}`) are split.
  Dead labels (defined but never referenced) are WARN-only since
  they're often intentional anchors for future work.

```
python ci/link_integrity_check.py
python ci/link_integrity_check.py --strict --verbose --venue-year 2026
```

Output: `ci/link_integrity_results.json`.

### L9 — Cross-claim consistency (`cross_claim_consistency_check.py`)

Verifies that formula-claims and value-claims agree numerically.
The previous layers verify each claim individually appears in the
paper; L9 verifies they don't contradict each other.

Example: C1 says δ_min = sqrt(2/(1-ρ)), and I11-I15 list discrete
values for ρ ∈ {0, 0.3, 0.5, 0.7, 0.9}. L9 evaluates the formula at
each ρ and checks the result matches the documented value within
tolerance. If C1's formula drifts to sqrt(3/(1-ρ)) but I11-I15
don't update — or vice versa — the paper now contains contradictory
statements. L9 catches that.

Hand-curated declarative table maps formula-claims to their numerical
instances. Each `ConsistencyRelation` carries:
  - the formula (Python-evaluable expression)
  - parameter values (e.g. `{rho: 0.5}`)
  - expected numerical value
  - tolerance (default 1e-3 abs/rel)
  - claim IDs the relation ties together

Current relations (16):
  - C1 (sqrt(2/(1-ρ))) ↔ I11-I15 boundary table (5)
  - C2 (sqrt(k)) ↔ I31-I35 k-scaling table (5)
  - C7 generalized formula ↔ C1 boundary case at k=2 (1)
  - I7-I10 tier rows: pass% + fail% sum to 100% (4)
  - T13 reported r_s vs results JSON value (1)

Out of scope: extracting formulas automatically from main.tex prose.
That requires a LaTeX math parser, and most paper formulas need
human judgment to encode (which symbol is the variable, which is
the parameter). The cost of one row per relation is small; the
benefit is catching the entire class of "theory and numbers got out
of sync" bugs that none of L1-L8 see.

```
python ci/cross_claim_consistency_check.py
python ci/cross_claim_consistency_check.py --verbose
```

Output: `ci/cross_claim_consistency_results.json`.

### L6 — Unified certificate (`claim_certificate.py`)

Runs L1-L5 in sequence, aggregates their summaries, and emits a
structured certificate in two formats:

- `ci/claim_certificate.json` — machine-readable, includes paper
  sha256, registry sha256, paper PDF size, generation timestamp,
  per-layer status, per-figure coverage breakdown
- `ci/claim_certificate.md` — human-readable summary

Aggregate verdict: **PASS** / **WARN** / **FAIL**

- **PASS** — all structural layers (L1, L2, L4) clean AND coverage
  thresholds met (L3 ≥60%, L5 ≥50%)
- **WARN** — structurally clean but a coverage layer is below threshold
- **FAIL** — any structural layer failed

The certificate is what could ship in supplementary as a reproducibility
artifact: it documents which numeric claims have been mechanically
verified, which figures have lineage-traced data → script → asset chains,
and which numerics remain uncovered for human triage. The hashes give
reviewers a way to verify the certificate matches the version of the
paper they're reading.

```
python ci/claim_certificate.py
```

## Reproducing the certificate

From the repo root:

```
python ci/claim_certificate.py
```

Or any individual layer:

```
python ci/claim_audit.py --tier all
python ci/claim_audit_validator.py
python ci/claim_coverage_sweep.py
python ci/figure_lineage_check.py
python ci/figure_value_check.py
```

Each script writes its own JSON output alongside its source. Layer
exit codes:

| Layer | Exit 0 | Exit 1 |
|---|---|---|
| L1 | All claims found (with or without DRIFT) | One or more claims MISSING |
| L2 | All 13 structural checks pass | Any check failed |
| L3 | Always (advisory) | Never (advisory) |
| L4 | All checks pass + figures fresh | Stale asset, missing file, or orphan |
| L5 | Always (or `--strict` and zero uncovered) | `--strict` and any uncovered |
| L6 | Verdict PASS or WARN | Verdict FAIL |

## Extending the certificate

### Add a new claim

1. Decide the tier (critical = paper headline; important = table cell or
   appendix headline number; complete = exhaustive cell-level)
2. Add an entry to `CLAIM_AUDIT.md` in the appropriate tier table
3. Add a regex-pattern entry to `CLAIMS` (Tier 1) or `IMPORTANT`
   (Tier 2) in `claim_audit.py`
4. Update the `assert len(...)` count at the bottom of the list
5. Update the count in `CLAIM_AUDIT.md`'s header table
6. Re-run `python ci/claim_audit_validator.py` — should pass
7. Re-run `python ci/claim_audit.py --tier all` — your claim should
   appear FOUND

If the claim is documented in supplementary materials but not in
main.tex, add `"supplementary_only": True` to skip it from the
main.tex audit while keeping it tracked.

### Add a new figure

1. Add `\includegraphics` to main.tex
2. Add a corresponding entry to `ci/figure_lineage.json` with:
   - `asset` — relative path to the rendered file
   - `script` — the generation script
   - `data` — list of input file paths the script reads
   - `data_known` — true if all data deps are declared, false if
     dependencies are script-arg-driven and unknown
   - `outputs_secondary` — any results JSON files the script also
     writes (these go into `CLAIM_AUDIT.md` Data File Mappings too)
   - `main_tex_ref` — the path string used in `\includegraphics`
3. Re-run `python ci/figure_lineage_check.py` — B1 (orphan check)
   should pass

For TikZ figures (source IS the asset), set `tikz_source: true` and
omit the script/data fields.

### Add a new data file mapping

Add a row to the `# Data File Mappings` table in `CLAIM_AUDIT.md`.
Format:

```
| filename | `relative/path/to/dir/` | claim IDs it backs |
```

L2's check_data_files_exist will verify the path resolves.

## Optional: pre-commit hook

A pre-commit hook is provided at `ci/hooks/pre-commit`. When installed
it runs the three structural layers (L1, L2, L4) before each commit
and blocks the commit if any layer FAILs. Total wall time: <5 seconds.

Install:
```
cp ci/hooks/pre-commit .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

To bypass once (WIP commit): `git commit --no-verify`.

The advisory layers (L3 sweep, L5 figure values) are skipped to keep
commits fast. Run the full `python ci/claim_certificate.py` when you
want the complete picture.

## Known limitations

- **L3 long tail is noise**. ~507 uncovered numerics, but most are
  axis-tick sequences in figures, math constants in formulas, or
  enumeration markers. Top-30 ranked-by-priority is the actionable
  list. A future improvement would be arithmetic-progression
  detection (filter sequences like 0, 5, 10, 15, 20...).

- **L5 schematic figures show low coverage**. Algorithm storyboards
  and k-axis bar charts have mostly numerical axis labels, not
  empirical claims. Coverage % isn't meaningful for these.

- **Tier 3 (325 complete claims) is documented in CLAIM_AUDIT.md but
  not yet pattern-coded**. The audit harness only walks Tiers 1+2
  (100 claims). The L3 sweep's high-priority triage list is the
  natural input for Tier 3 expansion.

- **Audio binary assets verified by Path.exists() only** — they're
  marked `binary_asset: true` in the manifest as documentation that
  they should never be Read() (would burn millions of tokens for
  zero certificate value). The two paper-named .wav files are
  tracked; the other 29 are regenerable from `sonification.py`.
